# SEO / GEO / AEO — Scan Perks

Imported from the seo-geo skill (Generative Engine Optimization: answer-first passages, FAQ schema, crawler access, comparison tables, no keyword stuffing). This project overrides that skill wherever they conflict.

## Project overrides (these win)

1. Prices, trial length, scan caps, and whether customers must install the app come only from `src/data/site-facts.ts` and `phrases`. Never hard-code them. Never invent venue counts, member counts, testimonials, or repeat-visit percentages.
2. A competitor price is allowed only when the page already cites an amount, an https source, and a checked-on date. Otherwise write "price to confirm".
3. Do not add meta keywords tags. Do not add a FAQ that repeats a question already on the same page.
4. One primary CTA label: "Start free trial".
5. Customers collect stamps in the installed Scan Perks app. Do not say the browser adds a stamp.
6. Do not promise rankings or AI citations. Use Search Console exports for clicks, impressions, CTR, and position. Do not invent search volume.
7. Princeton GEO percentages (cite sources, statistics, quotations) are research claims. Do not print them on the marketing site as Scan Perks results.
8. `llms.txt` and `ai.txt` are generated by `src/pages/llms.txt.ts` and `src/pages/ai.txt.ts`. Edit those files, not deleted static copies.

Work from the latest Search Console export. Priority is pages already on page 1–2 with impressions and a weak CTR, then commercial queries still outside the top 10.

Buyer queries ("which coffee chain", "frequent buyers") must be answered honestly in the first sentences, then point owners to the product. Do not pretend Scan Perks is a chain rewards account.

## Page shape

- Title about 50–60 characters. Put the query words first. Put Scan Perks in the title when the query is branded or the result sits on page 1 with no clicks.
- Meta description about 150–160 characters. One fact, one difference, the trial.
- First 40–60 words answer the question the query asks. Then explain.
- One H1. Question-style H2s only when they match a real query.
- Comparison tables for "vs" and "alternatives" queries.
- FAQ answers are self-contained and use `phrases` for numbers.
- Internal links point at the primary URL, not a redirected duplicate.

## Crawlers

`public/robots.txt` should keep Google, Bing, PerplexityBot, OAI-SearchBot, ChatGPT-User, GPTBot, ClaudeBot, and Google-Extended allowed unless the user says otherwise. Confirm a token against the vendor's current docs before adding a new one.

## Workflow

1. Read `site-facts.ts` and the latest performance export before editing copy.
2. Change the title, description, opening answer, and one matching FAQ or H2 on the URL that already receives the impressions.
3. Update `ai.txt.ts` and `llms.txt.ts` so the cited URL matches that page.
4. Build with `npm run build`. Do not claim the live site changed until the commit is deployed.
